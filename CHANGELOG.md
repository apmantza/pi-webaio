# Changelog

All notable changes to pi-webaio will be documented in this file.

## [Unreleased]

### Added

- **Source trust-tier and evidence-quality grading** (`src/source-trust.ts`) — new `classifySourceProfile()` grades a result set into coarse trust tiers (`authoritative` / `credible` / `mixed` / `community`, mapped from the existing `sourceType` via `trustTierForSourceType()`) and emits deduped, fixed-order evidence-quality caveats — `community-only` (no authoritative/credible source in the set), `low-diversity` (≥2 sources concentrated on one domain >half share, or all one source type), `bot-check` (a source carries an unreachable/bot-blocked reachability signal — never invented: no data ⇒ never fires), and `possible-conflict` (conservative: a source's identity-bearing domain token appears as a whole ≥4-char query term) — plus diversity metrics (`uniqueDomains`, `topDomainShare`). Reuses `classifySourceType`/`extractDomain` from `search.ts` (no duplication). `research.ts` `rankSources()` gains an opt-in `trustBoost` (default off — the default path is byte-identical) adding a small per-tier bonus (authoritative +0.1, credible +0.05, no penalties) to the reciprocal-rank score. Lays the grading groundwork for the planned iterative research loop (roadmap F2). 36 new tests.
- **Backend `doctor`** (`scripts/diagnose-backends.mjs`, `npm run diagnose:backends`) — dependency-free diagnostic (Node built-ins only) that probes the optional backends pi-webaio relies on and reports ✓ ok / ✗ missing / ⚠ warn / ⊘ skipped with actionable hints: GitHub CLI presence + `gh auth` status, Playwright importability + chromium install, and headless-Chrome/CDP binary + assets — all offline; search-engine (DDG/Brave/Yahoo/Bing) and Jina (`r.jina.ai`) reachability sit behind an opt-in `--live` flag so the default run never touches the network. ~3s per-probe timeout (`--timeout-ms` override), exit 0 always, and a `--strict` flag that exits 1 when a required backend (gh, Chrome) is missing. Probes are dependency-injected (`runCommand`/`existsSync`/`listDir`/`importModule`/`fetchImpl`) so command-running and formatting are testable offline (roadmap F4). 33 new tests.
- **Context7 + DeepWiki verticals** (`src/verticals/context7.ts`, `src/verticals/deepwiki.ts`, `src/verticals/registry.ts`) — two new keyless vertical extractors (registry grows 19 → 21). **Context7** resolves a library name → ID via `context7.com/api/v1/search`, then fetches docs (`/api/v1/<id>?type=txt&tokens=N`), honoring an optional `CONTEXT7_API_KEY` (Bearer) and sniffing a leading `{` to survive Context7 lying about content-type (handles both v1 `{content, metadata}` and v2 `{codeSnippets, infoSnippets}` shapes). **DeepWiki** speaks minimal MCP Streamable-HTTP JSON-RPC (`initialize` → `notifications/initialized` → `tools/call ask_question {repoName, question}`) to `mcp.deepwiki.com/mcp`, parsing both JSON and SSE (`data:`) bodies and normalizing file citations to markdown. Registered for `context7.com/<path>` and `deepwiki.com/<owner>/<repo>` URLs (DeepWiki takes the question from `?q=`/`?question=`, defaulting to an overview). 22 new offline tests (roadmap F9).
- **Domain-diversified search ranking** (`src/search.ts`) — `scoreAndRankResults` now ends with an `applyDomainDiversityCap()` pass (default `DOMAIN_DIVERSITY_CAP = 2`, overridable via `options.domainCap`, `0` disables) that keeps the first N results per domain in the top slice and defers excess same-domain results to the end in score order — nothing is dropped, so recall is preserved while one domain can no longer dominate the top; domains are normalized via `stripWww`. A small `src/bm25.ts` relevance score over title + snippet is folded into the composite as a tiebreak among similarly-scored results. Composes with the existing sourceType / preferred-domain / goggles scoring; no existing ranking tests needed changes. 11 new tests (roadmap F5).
- **Content-hash dedup + `aio-webcontent` diff-mode** (`src/content-hash.ts`, `src/types.ts`, `src/session-store.ts`, `src/storage.ts`, `src/tools/webcontent.ts`) — fetched content is now SHA-256-hashed (`contentHash`, via `node:crypto`; `shortHash`/`contentUnchanged`/`hashesEqual` helpers, the last tolerant of the storage layer's truncated digests); on overwrite the prior version is retained (`previousContent`/`previousContentHash`) as a diff baseline, identical re-stores are detected (no spurious baseline), and legacy/disk entries get a backfilled hash. `aio-webcontent` gains an opt-in `diff: true` returning a section-level diff vs the previous version (reusing `src/content-diff.ts`, not reinvented), and now exposes `contentHash`/`unchanged`/`hasPreviousVersion` in `details`. Default retrieval is unchanged. 16 new tests (roadmap F6).
- **Local-knowledge pre-check before live fetch** (`src/tools/webfetch.ts`, `src/webquery-index.ts`) — `aio-webfetch` gains an opt-in `localCheck: true`: before any network I/O it resolves the pulled corpus for the target hostname (existing `resolveCorpusDir`) and runs a BM25 query (the fetch's `query`, or one derived from the URL path) via a new shared `queryIndex()` primitive added to `webquery-index.ts`. On a match the result carries `details.localKnowledge` (corpus dir, query, `matchCount`/`chunkCount`, and hits with file/url/heading/score) plus a `[Local knowledge pre-check: …]` note steering the agent toward the local corpus / `aio-webquery`. Byte-for-byte unchanged when the param is absent; pre-check failures (no corpus, no match, parse error) never block or alter the fetch. 10 new tests (roadmap F8).
- **Central `debug()` helper + subsystem tracing** (`src/debug.ts`, `src/strategy-memory.ts`, `src/session-store.ts`, `src/search.ts`) — new `debug(scope, …args)` / `debugEnabled()` gated on `PI_WEBAIO_DEBUG=1`, emitting namespaced lines to stderr (never stdout, which the MCP stdio server uses for JSON-RPC). Previously the flag was checked ad hoc in only `content.ts` + `paywall.ts`, so the two most common complaints — "why was this search engine missing?" and "why did this fetch take the browser path?" — left no trace even with debugging on. Strategy-memory rung selection / re-probe (`debug("strategy")`), session-cache hit/miss (`debug("cache")`), and search cooldown / skip / quota decisions (`debug("search")`) now all leave a trail. 3 new tests (observability audit P8).
- **Per-engine search status + latency** (`src/search.ts`, `src/tools/websearch.ts`) — `searchWeb` now returns an `engineStatus` map (`{ddg,brave,yahoo,bing}: {count, status, latencyMs}`, `status ∈ ok | empty | quota | cooled_down | error | disabled | http_<code>`) alongside the unchanged `ddgCount`/`braveCount`/… fields (backward-compatible). The tool renders a compact note for every non-`ok` engine — mirroring the existing `googleStatus`, e.g. `_(Brave: cooled down after recent failures)_`, `_(Yahoo: HTTP 429)_`, `_(Yahoo: returned 0 results)_` — and appends latency to ok-engine labels (`DDG:10 (1.2s)`). A down / rate-limited engine no longer looks identical to a legitimately-empty one; the per-engine `latencyMs` that was already measured is finally surfaced. 14 new tests (observability audit P2/P5).
- **`diagnose:backends` now probes the primary fetch layer** (`scripts/diagnose-backends.mjs`) — added offline probes for **wreq-js** (dynamic import + construct a session, no network; marked `required` so it gates `--strict`), **temp-dir / storage writability** (write→read→delete under the temp base), and **MCP SDK** importability, plus `--live` **DNS-resolution** and **proxy-env** (`validateProxyUrl`, http/https/socks5) checks. A broken wreq-js install previously reported all-green (`3 available, 0 missing`); it is now caught. All probes stay dependency-injected for offline testability. 17 new tests (suite now 52) (observability audit P3).
- **Browser-pool launch observability** (`src/browser-pool.ts`) — the background replacement-launch is no longer fully silenced (`.catch(() => {})`): failures are recorded in `lastLaunchError` / `degradedNotice` (surfaced in `stats()`) so `acquire()` can report a degraded pool instead of hanging silently, a successful launch clears it, and the channel-launch fallback reason + launch duration/channel are logged via `debug("browser-pool")`. Extracted pure helpers `toLaunchErrorRecord` / `degradedPoolNotice` / `formatLaunchTiming`. 14 new tests, shared with P7 (observability audit P4).
- **Bot-block fallback ladder summary** (`src/fetch.ts`) — the alternate-profile loop now accumulates `{profile, status?, error?}` for every rung (plain, each wreq fallback profile via `describeLadderError`, and the final Playwright attempt using the existing `statusOut` param) and, on total failure, emits a one-line ladder summary — `bot-block ladder exhausted for <host>: plain=blocked, firefox_147=403, …` — via a new exported `summarizeBotBlockLadder()`, so the user can judge whether `bypass: true` or a different `browser` profile would help instead of getting a generic bot-block error. Control flow is unchanged (still returns `null`); the soft-block-404 escalation (Rung 1c) is untouched. 14 new tests, shared with P4 (observability audit P7).
- **User-defined vertical load failures now warn** (`index.ts`, `src/verticals/registry.ts`) — `initUserExtractors()` warns (`[user-verticals] Failed to load user extractors: …`) on a loader throw instead of `.catch(() => {})` (gaining an injectable `loader` for testability), the top-level backstop catch warns likewise, and the per-match attribution swallow routes through `debug("verticals")`. A broken custom vertical (a documented feature) no longer silently falls through to the generic pipeline (observability audit P6).
- **Outline/TOC mode for `aio-webfetch` (UX1)** (`src/outline.ts`, `src/tools/webfetch.ts`, `src/tools/render-result.ts`) — new pure outline engine (`extractOutline` / `splitSections` / `renderOutlineText` / `countWords`) parses ATX headings into a heading tree with per-section word counts (ignoring headings inside fenced code, stripping the frontmatter / `[UNTRUSTED]` wrapper). A new opt-in `outline: true` param returns just that outline (~50 tokens) — the web equivalent of pi's `module_report` — so the agent can see a page's shape and fetch only the section it wants instead of a blind 1800-char teaser. The full content is still saved to disk + cached (only the returned view narrows) and re-wrapped in fresh `[UNTRUSTED WEB CONTENT]` markers. 23 new tests (UX audit UX1, issue #90).
- **Frugal default preview for long content (UX2)** (`src/tools/webfetch.ts`) — when extracted content exceeds `FRUGAL_PREVIEW_THRESHOLD_CHARS` (6000) and no `query` / `outline` / AI-summary applies, the returned preview is now the heading outline + the single largest section (truncated) instead of a blind 1800-char head-truncation; 1800–6000-char content keeps the existing teaser and an AI summary still wins when present. Conservative + threshold-gated; the full content is always saved + cached and the "retrieve with aio-webcontent" footer remains (UX audit UX2, issue #90).
- **Compact search mode (UX3)** (`src/tools/websearch.ts`, `src/search.ts`) — new opt-in `compact: true` on `aio-websearch` renders one line per result — `{n}. **{title}** — {url} [{sourceType}]` — with no snippet, for URL scouting (`max` cut count but not per-result verbosity). `sourceType` falls back to `classifySourceType` so it never prints `undefined`; the engine-count header + non-ok engine notes are kept. Extracted to a pure `renderSearchResults(results, {compact})` whose default branch is byte-for-byte the historical output. 6 new tests (UX audit UX3, issue #90).
- **Pre-fetch relevance signal (UX4)** (`src/tools/webfetch.ts`, `src/tools/render-result.ts`) — fetch results now carry `wordCount` + a compact heading `outline` in `details` (single-URL, answer-mode, 304, and diff paths), so the agent can judge whether a page is worth reading its body before spending the tokens (UX audit UX4, issue #90).
- **`Response ID` de-emphasized (UX5)** (`src/tools/webfetch.ts`) — the standalone `Response ID: …` line is dropped from the default markdown output (agents retrieve cached content by URL via `aio-webcontent`, rarely by ID); the ID remains in `details` and in the non-markdown / `json` format label (UX audit UX5, issue #90).
- **Trimmed preview frontmatter (UX6)** (`src/tools/webfetch.ts`) — `trimPreviewFrontmatter` strips low-value fields (author / published / site / language / word_count) from the preview's leading YAML only (title / url kept); the saved file keeps full frontmatter and the `[UNTRUSTED WEB CONTENT]` markers are never touched (UX audit UX6, issue #90).

### Changed

- **Jina proxy reader made lazy — local extraction runs first (perf P0, biggest win)** (`src/content.ts`, `src/fetch-jina.ts`) — `runHtmlPipeline` no longer calls `fetchJina` unconditionally *before* local extraction (it was re-fetching the already-downloaded page via `r.jina.ai`, measured ~4–5.5s/page then returning null 3/3 times). Local extraction (Readability → RSC → Defuddle → fallback, factored into `runLocalExtraction`) now runs first on the HTML in hand; Jina is tried **only** when the local pass yields < `MIN_LOCAL_WORDS` (50) words on a non-dangerous URL, and is preferred **only** when it recovers strictly more content (never downgrades a usable local result). `fetchJina` also gets a 4 s timeout (`JINA_TIMEOUT_MS`, vs the inherited 30 s, wrapped so a hang resolves `null` without a dangling rejection) and a bounded (LRU 50) per-domain negative cache so a domain whose Jina call returned null is skipped on subsequent pages of a pull. The v0.7.3 Cloudflare-challenge rejection + real-title resolution are untouched. Measured ~2.5 s/page saved (~52%) on locally-extractable pages (general-web p50 ~4.8 s → ~2.3 s). 9 new tests (perf audit P0, issue #89).
- **Defuddle bounded, Readability preferred (perf P1)** (`src/content.ts`) — `DEFUDDLE_TIMEOUT` tightened 8 s → 4 s, and the Readability "failed" heuristic (extracted to `readabilityRatioFailed`) lowered its content/HTML ratio threshold 1% → 0.5% (`READABILITY_MIN_RATIO`) while always accepting Readability at ≥ 50 words — so more pages resolve via the ~14×-cheaper Readability path (182 ms vs 2605 ms on 625 KB HTML) instead of falling through to Defuddle, bounding the p95/timeout tail (perf audit P1, issue #89).
- **Shared warm `BrowserPool` across single fetches + escalation (perf P2)** (`src/fetch.ts`) — a lazy process-level `getSharedBrowserPool()` singleton (maxBrowsers 1, constructed on first use) is now wired into all four browser escalations (remembered-`browser` fast-path, Rung-2 fallback, Rung-1c soft-block-404, bot-block fallback) via `resolveBrowserPool()`, so single fetches reuse a warm browser (~31 ms warm vs ~441 ms cold / ~808 ms per-request launch+close, ~14×) — ~740 ms saved per escalated fetch. Opt out with `PI_WEBAIO_SHARED_BROWSER_POOL=0`; an explicit `options.browserPool` still wins; `closeSharedBrowserPool()` + a process-exit hook drain it. **SSRF preserved:** the fail-closed `validateUrlForSsrf` pre-flight and the per-page `installSsrfRedirectGuard` run in *both* the pooled and per-request branches; only the defense-in-depth `--host-resolver-rules` IP-pinning is per-request (a pooled render that throws falls through to a pinned per-request launch). 6 new tests (perf audit P2, issue #89).
- **Per-engine search deadline (perf P3)** (`src/search.ts`) — each engine fetch is now wrapped in a `Promise.race` against `ENGINE_DEADLINE_MS` (4500 ms, unref'd/cleared on settle), so a stalled engine resolves to empty with a new `timeout` engine status — rendered `_(Bing: timed out after 4.5 s)_` through the existing `engineStatusNotes` helper (no websearch.ts change needed) — instead of holding the whole merge; a 429 stuck in `fetchWithRetry` backoff is cut off at the deadline (a fast in-window 429 still records as `quota`). Measured 1.5 s → 0.3 s with one slow engine. `searchWeb` gained an optional `{ fetchFn, engineDeadlineMs }` injection seam (backward-compatible — both callers pass 2 args). 7 new tests (perf audit P3, issue #89).
- **Right-sized `aio-webpull` concurrency (perf P4)** (`src/tools/webpull.ts`) — new pure `computePullConcurrency()` / `countDistinctHosts()` (wired into all three concurrency sites): single-host pulls use 10 workers (throughput is rate-limiter-bound at ~5/s per host, so the old `max(4, cpus×2)` = 32 workers only added lock contention — 8× workers bought 1.58× throughput); multi-host pulls scale to `distinctHosts × 10` bounded by CPU headroom (`max(4, cpus×2)`) and a 32 ceiling. The deliberate 5/s per-host politeness cap is unchanged. 15 new tests, shared with P5 (perf audit P4, issue #89).
- **Restored dead 304 revalidation + cache audit (perf P5)** (`src/http-validators.ts`, `src/tools/webfetch.ts`) — the revalidation prologue called `getStoredContent()` (which *evicts* expired entries as a side effect) immediately before `peekStoredContent()`, so the peek always saw `null` and conditional-304 revalidation never fired (dead code). New `getRevalidationCandidate()` peeks without evicting (expired + has-validators), restoring the 304 path; the rest of the cache was audited and is well-used (default path intentionally fetches fresh per webfetch's contract; cache is served via `aio-webcontent` + 304). 15 new tests, shared with P4 (perf audit P5, issue #89).

### Fixed

- **Batch fetch errors now carry the phase-aware error code** (`src/tools/webfetch.ts`) — the multi-URL batch result's `Errors:` list read the legacy `errorInfo.code`, so an SSRF block rendered as `[invalid_url]` while the single-fetch path correctly showed `[blocked_ssrf]`. The batch renderer now prefers the phase-aware `fetchError.code` / `fetchError.statusCode` (falling back to the legacy fields), so a blocked URL renders `[blocked_ssrf]` consistently across single and batch fetches.
- **Soft-block 404s now escalate to the headless browser** (`src/fetch.ts`) — Vercel / Next.js edges (e.g. `react.dev`) return a bare HTTP 404 to `wreq-js` TLS-fingerprinted requests that a real browser receives as 200. `fetchWithRetry` treats 404 as non-retryable and hands the response back, so `smartFetch`'s existing `!res` browser rung never fired and the 404 surfaced as a terminal `http_error` — a top-tier docs site failed out-of-the-box on the default `auto` path. `smartFetch` gains a Rung 1c: on a wreq-rung 404 it escalates once to `fetchWithPlaywright` (which now reports the browser's `response.status()` via an optional `statusOut` out-param) and accepts only a 2xx render via a new exported `isSoftBlock404Resolved()` predicate. A genuine 404 also 404s in the browser, so the predicate stays false and the original 404 is returned (fail-fast preserved); a resolved soft-block records a `browser` domain success so strategy-memory skips straight to the browser next time. Opt out with `PI_WEBAIO_404_BROWSER_ESCALATION=0`. Verified live: `react.dev/` 404 → 200 (272 KB), `react.dev/<bogus>` stays 404. 8 new tests.
- **`aio-webfetch` batch aborted when one URL threw** (`src/tools/webfetch.ts`) — a URL that throws during fetch (e.g. the SSRF guard throwing `blocked_ssrf`) rejected `runInBatches`' bare `Promise.all`, so the outer catch mis-attributed a single error to `targets[0]` and every other URL in the batch was silently lost (`Fetched 0/2` with one error — a good URL batched with a blocked one never fetched). The per-URL handler now wraps `pullPageEnhanced` (and its browser-retry) in a try/catch that converts a thrown `FetchError` into that URL's error result, so the remaining targets complete (`Fetched 1/2`, each failed URL carrying its own phase-aware `[blocked_ssrf]` error). Same failure class the B3 fix guarded in `aio-webresearch`; the `aio-webfetch` batch path was never guarded. Verified live: `[169.254.169.254, example.com]` → `1/2`. 2 new offline tests drive the real execute handler (captured via the MCP mock-pi shim).
- **Batch result count can no longer lie — P1 defensive backstops** (`src/tools/webfetch.ts`) — on top of the per-URL throw-guard above, two audit-recommended backstops: (a) `backfillMissingResults()` runs right after `runInBatches` and guarantees one result slot per target, synthesizing `{ ok:false, error: "no result recorded (internal error)" }` for any missing/undefined slot so the rendered `Fetched N/M` count can never under-report; (b) the error-render loop calls `detectErrorMisattribution()` and appends `[error references a different URL]` when an error message names a different http(s) URL than its own (the audit reproduced a case where a good URL was labeled with a bad URL's `blocked_ssrf` message). Both helpers are exported and pure. 9 new tests, shared with P6/P8 (observability audit P1).
- **wreq-js native connection errors now classified as retryable** (`src/fetch.ts`) — `isRetryableNetworkError` matched only Node-style error strings (`ECONNRESET`, `ETIMEDOUT`, …), but the wreq-js native (Rust/reqwest) binding reports transport failures in its own format — `error sending request for uri (…)`, `An existing connection was forcibly closed by the remote host. (os error 10054)`, `Connection reset by peer` — none of which matched. A wreq-js connection reset was therefore treated as non-retryable: `fetchWithRetry` failed fast with no retry, and the throw bypassed `smartFetch`'s `if (!res)` browser rung, so a fingerprint-only block died immediately instead of escalating to the browser. The classifier now recognizes the wreq-js phrasings and lower-cases the message first (so the uppercase `ECONNRESET`-style codes still match), giving these errors their normal retries + browser escalation. Diagnosed via a DuckDuckGo connection-reset from the audit host — note DDG itself is IP-blocked there (the headless browser is reset too), so this fixes the general mis-classification, not that specific environment block. 3 new tests.

## [0.7.3] - 2026-07-29

### Added

- **Omitted-sections index on markdown truncation** (`src/prune-markdown.ts`) — when `pruneMarkdown` drops sections to fit a token budget, the truncation footer now appends a mini table-of-contents of the omitted section headings (indented by heading level, in document order, capped at 20 entries with a "…N more" overflow line) so the agent knows *what* was left out, not just how many sections were cut. Two prune tests refined to assert on pruned section *bodies* (headings may legitimately survive in the index). Inspired by henyo-pi-web's residual-heading TOC (roadmap F7).
- **Scheduled Dependabot version updates** (`.github/dependabot.yml`) — weekly npm (minor/patch grouped) + github-actions update PRs, adding a proactive cadence on top of the existing reactive security-update PRs (which had been opening but sitting unmerged).
- **Secret redaction in tool output and error messages** (`src/redact.ts`, `src/tools/fetch-error.ts`, `src/tools/render-result.ts`) — complements the existing pre-flight secret *blocker*: a self-contained `redactSecrets()` now masks credentials (Authorization headers, JWTs, private-key blocks, password-in-URL userinfo, and entropy-guarded `api_key`/`token`/`secret`/`password` key-value forms) that appear in user-facing error messages and rendered TUI previews/URLs, so a credential that slips through in a response or error never lands in the agent's context. The block-on-secret scanner is unchanged; redaction is additive masking. 21 new tests.

### Changed

- **`aio-websearch` surfaces a requested-but-empty Google** (`src/tools/websearch.ts`) — when `google: true` is requested but Google yields nothing, the result now carries a `googleStatus` field (`disabled` / `unavailable (Chrome CDP not present)` / `unavailable (provider cooled down…)` / `empty (Google returned 0 results)` / `error (…)`) in `details` and appends a `_(Google: requested but returned nothing — <status>)_` note to the output, instead of silently dropping Google from the engine list. A silent zero no longer looks like Google was never attempted (roadmap B4).
- **Dependency security bumps** (`package.json`) — removed the unused `sharp` dependency entirely (it was declared but never imported; clears a high-severity libvips advisory and drops a heavy native binary); bumped `@modelcontextprotocol/sdk` to ^1.30.0 and pinned `@hono/node-server` ^2.0.5 and `brace-expansion` ^5.0.8 via `overrides` (clears the moderate Windows path-traversal and high DoS advisories). The `brace-expansion` copy nested under the `@earendil-works/pi-coding-agent` **peer** cannot be governed by our overrides (confirmed even after a clean lockfile regen) and is accepted as an upstream/transitive-peer advisory.
- **Raised pi peer/runtime floor to 0.82** (`package.json`) — peer `@earendil-works/pi-coding-agent` and dependency `@earendil-works/pi-tui` bumped `^0.79.0` → `^0.82.0`; the old caret-on-`0.x` range resolved to `<0.80.0` and excluded the current pi (0.82.1).
- **Raised pi peer/runtime floor to 0.83** (`package.json`) — peer `@earendil-works/pi-coding-agent` and dependency `@earendil-works/pi-tui` bumped `^0.82.0` → `^0.83.0`; the old caret-on-`0.x` range resolved to `<0.83.0` and excluded the current pi (0.83.0). pi 0.83.0's TypeBox breaking change (removed `Type.Base` / `Awaited` / `Promise` / `AsyncIterator` / `Iterator` / `Options` and `Value.Mutate`) does not affect pi-webaio — it uses only supported TypeBox APIs (`Object`/`String`/`Number`/`Boolean`/`Optional`/`Array`/`Union`/`Unknown`/`Record`); all 8 tools verified working live under 0.83.0.
- **SSRF guard hardened: DNS-pinning, fail-closed, non-overridable metadata floor** (`src/security.ts`, `src/fetch.ts`) — `validateUrlForSsrf()` resolves DNS once and validates every returned address, returning the validated IPs as `pinnedIps`; `createPinnedLookup()` dials exactly those validated addresses (closing the re-resolve TOCTOU where DNS could return a safe IP at validation and an internal one at connect), wired into the Playwright fallback via Chromium `--host-resolver-rules` (the `wreq-js` primary fetcher is a native binding with no lookup hook, so it keeps the fail-closed pre-flight check). The guard fails closed on any abnormal condition (DNS error, empty answer set, unparseable URL, unexpected throw), and the cloud-instance-metadata block (169.254.169.254, AWS IMDSv6 `fd00:ec2::254`, IPv4-mapped forms, `metadata.google.internal`) is an absolute floor evaluated *before* the CIDR allow-list, so `WEBAIO_SSRF_ALLOW_RANGES` can never relax it. 30 new offline tests.

- **Search-context summary bridging is now relatedness-gated** (`src/session-store.ts`, `src/tools/webfetch.ts`) — the recent `aio-websearch` query is injected into a page's AI summary only when it is actually related to that page, scored via the existing BM25 machinery (`src/bm25.ts`) over the page's URL + title + first heading against a conservative threshold (0.35, calibrated so a lone weak term is skipped while a genuine topical match injects). An unrelated recent search no longer biases the summary toward its own topic. When context is injected the summary is annotated `_[focused on prior search: "…"]_` so downstream agents know it is not neutral, and `summaryCache` is now keyed by URL + context (null-byte-separated, so a focused key can never collide with the bare-URL no-context key) — a focused summary is never served for a context-free request. The no-context path is byte-for-byte unchanged.

### Fixed

- **Cloudflare challenge pages accepted as content with a hostname title** (`src/fetch-jina.ts`, `src/content.ts`) — `runHtmlPipeline` calls Jina first and returns unconditionally, and `fetchJina` defaulted the title to the hostname when the body lacked a `Title:` line; `r.jina.ai` currently returns Cloudflare managed-challenge HTML with a status <400 that passed the `status >= 400` guard, so the challenge page became the 'content' with a hostname title and readability/RSC/defuddle never ran (systematic across SPA blogs, static docs, and example.com). `parseJinaBody()` now rejects bodies that lack a `Title:` line AND match challenge markers (`detectBotBlock` plus a focused single-marker check), returning `null` so the real pipeline runs (correct content AND title), and the RSC branch resolves a real title (`og:title` → `<title>` → `<h1>` → hostname) instead of hardcoding the hostname for Next.js SPAs. 10 new offline tests.
